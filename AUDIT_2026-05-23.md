### 1.4 [VÉRIFIÉ] `src/inpi.py:474` — proxy de CA dégradé en fallback `total_produits_exploitation` introduit un biais

Ligne 474 :
```python
ca = bilan.get("ca_net") or bilan.get("total_produits_exploitation")
```

Si `ca_net` (FJ.m3) est extrait correctement, OK. Si FJ est absent (cas rares), on retombe sur FR (total produits exploitation = CA + subventions + reprises + autres produits). Pour ENERFLUID 2024 (test exécuté) :

**Correction suggérée** : retirer le fallback ou le tracer explicitement avec un flag `ca_fallback=True` pour que la cible soit marquée "à requalifier manuellement".

## 2. Hallucinations probables (codes/libellés non vérifiés contre source officielle)

### 2.1 [À CONFIRMER] `src/inpi.py:42-66` — codes RNE `30`, `74`, `99`, `110` documentés "empiriques"

Le commentaire en tête de `ROLES_RNE` précise : *« La nomenclature officielle INPI roleEntreprise n'est pas publiée dans la doc API v4.0 »*. Les libellés "Cosignataire / pouvoir d'engagement" (code 70), "Représentant légal (PM dirigeante)" (code 110), etc. sont des inférences.

Risque : un dirigeant légitime mappé à "autre" sera mal classé en `is_direction=False`, et la cible sera exclue par erreur. Le commentaire mentionne 285 occurrences du code 30 sur SARL alors que l'« associé indéfiniment responsable » légal n'existe que pour SNC/SCS — donc le libellé "Associé / pouvoir d'engager" est de toute façon ambigu sur SARL.

**Recommandation** : soit obtenir le référentiel officiel INPI (demande par mail à l'INPI), soit afficher explicitement dans l'UI un encart "Mapping rôles INPI partiellement empirique — voir la doc API si rôle = ?".

### 2.2 [VÉRIFIÉ] Inversion N/N-1 chez `societe.com` (pas un bug de l'app, mais à connaître)

Test croisé entre TECHNICAIR (SIREN 692051394) sur :
- Mon code : bilan 2024 → CA 3 978 986 €, REX 225 345 €
- `societe.com` : affiche pour "2024" → CA 4 119 000 €, REX 327 500 €

Investigation : sur le bilan 2024 de TECHNICAIR, `m3` (N) = 3 978 986, `m4` (N-1) = 4 119 021. Sur le bilan 2023, `m3` (N=2023) = 4 119 021. Donc **société.com affiche en colonne "2024" la valeur N-1**, c'est une erreur de société.com, pas du code Sourcing. Conséquence : si Bastien compare les chiffres avec societe.com, il aura un décalage d'un an. À documenter dans une note ou un tooltip.

Validation croisée OK sur :
- ENERFLUID 2023 : CA 5 082 216 € (mon code) = 5 082 000 € (societe.com) ✓
- PPF 2022 : CA 2 678 016 € (mon code) = 2 678 000 € (societe.com) ✓
- TECHNICAIR 2023 : CA 4 119 021 € (mon code, vu en m3 du bilan 2023) = 4 119 000 € (societe.com affiché en "2024") — décalage de 1 an chez societe.com

### 2.3 [À CONFIRMER] `src/inpi.py:526-587` — niveaux `section/detail/subtotal/total/key` partiellement subjectifs

La hiérarchie visuelle dans `COMPTE_RESULTAT_LIGNES`, `BILAN_ACTIF_LIGNES`, `BILAN_PASSIF_LIGNES` est cohérente avec le CERFA 2050-2053 (validée à l'œil sur structures officielles : Produits d'exploitation / Charges d'exploitation / Résultat d'exploitation / RCAI / Résultat net). Mais l'absence de blocs "Produits financiers / Charges financières / Résultat financier" et "Produits exceptionnels / Charges exceptionnelles / Résultat exceptionnel" dans `COMPTE_RESULTAT_LIGNES` donne un CR amputé — passé directement de REX à RCAI à Résultat net sans détail des rubriques financières et exceptionnelles.

Pas un bug en soi (le code n'a pas extrait ces lignes), mais un Excel "comptes annuels" sans les rubriques financières/exceptionnelles peut surprendre Bastien. **Recommandation** : soit ajouter les codes FT/FU/FV (variation stocks), GH-GV (rubriques financières et exceptionnelles), soit afficher un encart "Excel pédagogique — voir liasse PDF pour le détail complet".

### 2.4 [VÉRIFIÉ] `src/inpi.py:417` — statut "Publication simplifiee" assimilé à "Public"

Le commentaire dit *« Publication simplifiée = bilan public mais allégé (entreprises < 6 M€ CA option L.232-25) »*. **C'est exact** au regard de l'article L.232-25 C. com. ## 3. Améliorations recommandées (non bloquantes)

### 3.1 [VÉRIFIÉ] Aucun test automatisé (`tests/` vide)

Pour un partage à un associé externe, l'absence totale de tests unitaires est inhabituelle. A minima, recommander : 5-10 tests `pytest` couvrant `extract_bilan` (cas C, S, K), `compute_ratios` (cas EBE négatif, CA nul, etc.), `filter_entreprises_par_geo`, `_str_to_int` (cas limites). Bastien pourra ainsi modifier le code sans risque de régression silencieuse.

### 3.2 [VÉRIFIÉ] `app.py:476-526` — couplage fort dans le bloc `if lance:`

Le bloc principal (498 lignes 477-625 = 150 lignes dans une seule cellule "if") mélange pull API, login INPI, lookup en boucle, ratios, persistance session_state. Refactor recommandé en 3 fonctions séparées : `run_screening(params) → dict[str, list]` (pure), `affichage_resultats(data)` (UI), `download_handlers(data)` (UI). Améliore lisibilité et testabilité.

### 3.3 [VÉRIFIÉ] Aucune limite sur le volume d'entreprises pulled

Si Bastien lance un screening "France entière, code NAF très large, sans filtre effectif" → l'API peut renvoyer 10 000+ entreprises, puis le lookup INPI tournera potentiellement 10-30 minutes sans interruption possible. Recommander un garde-fou (`if len(entreprises) > N_MAX: st.warning(...) && st.stop()`).

### 3.4 [VÉRIFIÉ] `app.py:475` — bouton "Lancer le screening" sans confirmation

Aucun garde-fou si Bastien clique deux fois — chaque clic relance tout le pipeline. Recommander un `st.session_state["running"]` pour désactiver le bouton pendant l'exécution.

### 3.5 [VÉRIFIÉ] `src/api_gouv.py:50-75` — pagination par fetch immédiat sans interruption

La boucle `for page in tqdm(range(2, total_pages + 1))` n'a pas de circuit breaker. Si l'API tombe à la page 30/200, on perd tout. Recommander un cache incrémental par page (sauvegarder le batch déjà récupéré dans le cache pour reprise).

### 3.6 [VÉRIFIÉ] `cli.py:43-110` — désynchronisation avec `app.py`

`cli.py` n'a jamais été mis à jour pour intégrer le filtre géographique (régions/départements), la recherche par mots-clés, l'enrichissement INPI. Il ne fait que l'échantillon 1. Recommander soit de mettre à jour, soit de marquer en doc "CLI legacy : pour usage complet, utiliser `streamlit run app.py`".

### 3.7 [VÉRIFIÉ] Pas de mise en cache du JWT INPI

`_login()` est appelé à chaque session ; le JWT est gardé en mémoire mais perdu au reload de la page Streamlit. Pour Streamlit Cloud où les sessions peuvent être courtes, recommander une mise en cache du JWT dans `st.cache_resource` avec TTL de 50 minutes.

### 3.8 [VÉRIFIÉ] Documentation CERFA limitée dans `inpi.py`

Le commentaire ligne 256-270 décrit la convention m3/m4 pour le régime normal, mais l'audit a montré que la convention diffère entre page 1 et page 3 du même régime (m3 = Net dans les 2 cas, mais m4 = N-1 page 3 ≠ m1 = N page 2). Étoffer le commentaire avec un tableau exhaustif (cf. section 1.1).

### 3.9 [VÉRIFIÉ] Pas de version pinnée dans `requirements.txt`

Toutes les dépendances en `>=`. Sur Streamlit Cloud, le rebuild risque de récupérer une version majeure incompatible (pandas 3.0, streamlit 1.50). Recommander de pinner aux versions actuellement déployées (`pip freeze > requirements.lock`).
