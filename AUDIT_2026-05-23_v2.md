## 1. Bugs critiques restants (à corriger avant Bastien)

### 1.1 [VÉRIFIÉ] `src/inpi.py:394-400` — bilans de type `K` mal routés (mapping faux)

Le code route les deux types `S` et `K` vers `LIASSE_SIMPLIFIE_CODES` :

```python
if type_bilan in ("S", "K"):
    codes_map = LIASSE_SIMPLIFIE_CODES   # codes 028, 044, 210, 232... (régime simplifié 2033)
    page_col = LIASSE_PAGE_COL_N_SIMPLIFIE
else:
    codes_map = LIASSE_NORMAL_CODES      # codes BV, BX, DA, FJ, GG... (régime normal 2050-2053)
```

**Observation factuelle** sur le cache INPI réel (`data/cache_inpi/attachments_*.json`) :

| codeTypeBilan | Codes effectivement présents | Mapping correct |
|---|---|---|
| `S` | 028, 044, 060, 110, 142, 210, 218, 232, 264, 270... | `LIASSE_SIMPLIFIE_CODES` ✓ |
| `K` | DA, DF, DL, DM, BJ, FA, FJ, FR, AT, BH, CD, CO, FW... | **`LIASSE_NORMAL_CODES` requis** ✗ |

Test exécuté sur NOVETUD (SIREN 321304016) — un bilan K 2022 avec `detail` rempli (4 pages, 50 liasses) :
- Extraction actuelle (route vers SIMPLIFIE) → `ca_net=None, rex=None, capitaux_propres=None`, **0 codes matched**
- Si on force le mapping NORMAL → CA = 31 062 681 €, REX = 2 294 993 €, CP = 32 841 719 € (22 codes matched)

**Volumétrie observée** : sur 41 fichiers attachments parcourus, 5 bilans K trouvés, **tous** non extractibles avec le mapping actuel. Sur les 12 bilans S/K avec détail, seuls 2 ont une extraction réussie (CA+REX), et ce sont des S 2016.

Le commentaire ligne 266-268 ([source]) suggérait `S ou K = régime simplifié`, ce qui se révèle factuellement faux d'après les données INPI réelles. Le type `K` (probablement « consolidé » ou « non-standard ») utilise en pratique le format normal 2050-2053.

**Correction suggérée** :
```python
# Ligne 395
if type_bilan == "S":
    codes_map = LIASSE_SIMPLIFIE_CODES
    page_col = LIASSE_PAGE_COL_N_SIMPLIFIE
else:  # C, K et tout autre type → mapping normal
    codes_map = LIASSE_NORMAL_CODES
    page_col = LIASSE_PAGE_COL_N_NORMAL
```

**Impact pour Bastien** : si son nouveau périmètre comprend des moyennes/grandes entreprises (NAF industrie, BTP, distribution), il rencontrera fréquemment des bilans K — et toutes ces cibles seront classées « bilan non public » à tort. Le pilote NAF 4669B n'est pas concerné (0 bilan K dans les 8 cibles retenues), mais le bug devient bloquant dès l'extension.

### 1.2 [VÉRIFIÉ] `enrich_echantillon_3.py:103` — `compute_ratios` appelé sans `multiple_ebe`

Le script CLI legacy `enrich_echantillon_3.py` appelle encore `cible["ratios"] = compute_ratios(bilan_data)` sans transmettre `multiple_ebe`, donc valeur par défaut 4.0 toujours utilisée. Non bloquant car ce script n'est plus utilisé dans le flow Streamlit, mais incohérent si Vladimir/Bastien l'invoquent en CLI. Corriger ou retirer.
